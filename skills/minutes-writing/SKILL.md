# 内部会议纪要

为 60 分钟以内的内部会议产出**决议与行动项优先**的纪要：谁定了什么、谁在什么时候做什么、什么没定下来。纪要不是流水账，是从讨论到执行的交接单。

与公文会议纪要的分工：机关、国企的正式"会议纪要"公文（红头、文号、版记）由 gongwen 排版层负责版式，本 skill 负责其中的会议内容部分；企业/团队内部例会、评审会、复盘会直接用本 skill 全流程。

## 铁律

1. **不编造决议和行动项。** 转写/笔记里没有的决定、责任人、日期不补。听不清或没提到就标 `[待确认]`。
2. **区分发言与结论。** 讨论过程压缩成要点，只有明确拍板的才算决议。
3. **不发布原始隐私。** 讨论中涉及的人事、薪酬等敏感内容，除非用户明确要求，不写入分发稿。

## 工作流

```
① 收集要素 → ② 追问缺口（≤3 问）→ ③ 按 schema 起草 → ④ 交主持人核对
```

### ① 收集要素

起草前先拿到：会议名称、日期、起止时间（或时长）、主持人、参会人/缺席人、分发对象。输入材料：议程、转写、录音整理稿或原始笔记。

### ② 追问缺口

以下任一缺失，最多追问 3 个问题再动笔：

- 会议名称、日期、时长、主持人是谁？
- 有议程或转写稿吗？有就请提供。
- 纪要由谁核发（审定人）？

用户回复"没有转写/没有议程"时照常起草，但材料来源标注"现场笔记"，并在文末提示可能的缺漏。

### ③ 按 schema 起草

按下面的结构输出，字段缺失用 `[待确认]`，不要用猜测填坑：

1. **基本信息**：会议名称 / 日期（YYYY-MM-DD，本地时间）/ 起止时间或时长 / 主持人 / 地点或会议链接 / 记录人 / 分发范围。
2. **出席情况**：出席（姓名+角色）、缺席、记录人。
3. **议程**：按顺序列条目。
4. **会议摘要**：1—3 句话概括会议目标与总体结果。
5. **会议决议**：逐条列出——决议内容 / 决定人或批准人 / 理由（1—2 句）/ 生效日期（如有）。
6. **行动项**：逐条列出，**每条必须有责任人和截止时间**——编号（如 A1）/ 事项 / 责任人（部门）/ 截止（YYYY-MM-DD 或"本周内"）/ 完成标准 / 关联工单或文档（如有）。

   示例：[A1] 起草功能 X 的上线回滚手册——责任人：李工（研发）——截止：2026-02-05——完成标准：含回滚步骤、健康检查与监控链接——关联：ISSUE-123。

7. **议题要点**：按议程逐条给关键发言与未决问题（带时间戳可选）。
8. **遗留问题（Parking Lot）**：没结论的事项——搁置原因 / 建议责任人或下次会议再议。
9. **风险与阻塞**（如有）：风险描述、影响、缓解责任人。
10. **下次会议**：拟定时间（如有）与议题目标。
11. **附件与引用**：议程、幻灯片、录音、关联工单的链接或 `无`。
12. **版本记录**：版本号、最后更新时间、修改说明。

### ④ 交主持人核对

含重要决议的纪要，定稿前请主持人或指定审定人快速核对（24 小时内）；核对重点是决议表述与行动项责任人。

## 风格规则

- 简洁：30 分钟以内的会 1 页内，接近 60 分钟的会不超过 2 页。
- 决议和行动项放文档前部——这是纪要的主价值。
- 平实语言 + 列表；不用推测性表述，不确定就 `[待确认]` 并注明缺什么。
- 日期统一 YYYY-MM-DD。

## 做 / 不做

**做：** 每个行动项都带责任人和截止时间；能给完成标准就给；用关联工单/文档保证可追溯；含重大决策时先送审再分发。

**不做：** 漏掉决议或行动项（那是纪要的核心价值）；把个人观点混进事实（要写就明确标注"某某意见"）；未经要求把讨论中的敏感个人信息写进分发稿。

## 验收标准

成稿合格当且仅当：

- 含基本信息、出席、决议、行动项四个部分；
- 每个行动项有明确责任人和截止时间或清晰时限；
- 重大决议至少附 1 行理由；
- 附件一节有列表或明确标"无"；
- 全文为事实记录，不确定处标 `[待确认]`。
