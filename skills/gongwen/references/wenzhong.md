# 12 个法定文种

GB/T 9704—2012 规定的 15 个文种里最常用的 12 个。**要素不同，不要套错。**

判断依据（参考 `cn-gov-soe-writing-router` 的材料类型判断）：
是否存在明确行文关系、是否正式印发、是否有主送单位、是请求批准还是报告情况或部署事项。

---

## 文种路由决策树（先看这里）

用户说「打个报告」「发个通知」往往不准确——按行文方向 × 行文目的路由：

```
问：向谁行文？（行文方向）
│
├─ 上行（给上级）
│   ├─ 要批准/要钱/要人 ──────────→ 请示（一文一事，只主送一个上级）
│   ├─ 汇报工作/反映情况/答复询问 ──→ 报告（不得夹带请示事项）
│   └─ 上级问什么答什么 ──────────→ 报告（答复性报告）
│
├─ 下行（给下级）
│   ├─ 布置工作/传达要求 ──────────→ 通知
│   ├─ 批转/转发文件 ────────────→ 通知（批转转发性）
│   ├─ 答复下级的请示 ────────────→ 批复（只答一件请示）
│   ├─ 表彰/批评/通报情况 ─────────→ 通报
│   ├─ 宣布重要事项/人员任免 ──────→ 决定
│   └─ 施行强制措施 ─────────────→ 命令（令）
│
└─ 平行（给不相隶属单位）
    ├─ 商洽工作/询问/请求批准 ─────→ 函
    └─ 答复对方来函 ─────────────→ 函（复函）
```

**易错点**：
- 「向上级打个报告要经费」→ 这是**请示**不是报告（要批准 = 请示）
- 「给平级单位发个通知」→ 平级用**函**，通知只向下行文
- 「会议纪要」不是独立行文的文种（纪要 = 会议议定事项的记载，GB/T 9704 单列）
- 请示和报告**不能混用**：请示要批复，报告不要批复

---

## 上行文（两个特例）

### 请示
- **不冠发文机关标志**（红头）
- **不设签发人**
- **一文一事**
- 只主送一个上级机关，不得同时抄送下级
- 不得与报告混用

### 报告
- **不冠发文机关标志**（红头）
- **不设签发人**
- 不得夹带请示事项（要批准的事另用请示）
- 报告可以多级主送

## 平行文 / 下行文

| 文种 | 方向 | 必有要素 | 注意 |
|---|---|---|---|
| **通知** | 下行、平行 | 发文机关标志、发文字号、标题、主送机关、正文、署名、成文日期 | 发布、转发、传达要求；转发要注明原文标题与发文字号 |
| **通报** | 下行、平行 | 同通知 | 表彰、批评、传达重要精神和告知重要情况 |
| **函** | 上下、平行 | 发文机关标志、发文字号、标题、主送机关、正文、署名、日期 | 商洽、询问、答复、关照；不相隶属机关之间用"函"不用"通知" |
| **批复** | 下行 | 发文机关标志、发文字号、标题、主送机关、正文、署名、日期 | 只答一件请示；标题写「XXX关于XXX的批复」 |
| **意见** | 上下、平行 | 发文机关标志、发文字号、标题、正文、署名、日期 | 指导性、倡导性；分条列项 |
| **决定** | 下行 | 发文机关标志、发文字号、标题、正文、署名、日期 | 重要事项用「一、」分层 |
| **命令（令）** | 下行 | 发文机关标志、发文字号、标题、正文、署名、日期 | 公布行政法规、宣布决定、任免人员；**限定受文范围** |
| **公告** | 向下公布 | 发文机关标志、标题、正文、署名、日期 | 向国内外宣布重要事项或法定事项；内容要简明 |
| **纪要** | 平行 | 标题、出席/列席/缺席、议定事项、署名、日期 | 只记议定事项，不记过程；议定事项用「一、」分层 |
| **议案** | 上下 | 发文机关标志、发文字号、标题、主送机关、正文、署名、日期 | 提请人大或常委会审议 |

## 要素顺序（通用）

```
发文机关标志（红头，红色）
  ↓ 空二行
发文字号
  ↓
红色分隔线
  ↓ 空一行
标题
  ↓ 空一行
主送机关
  ↓
正文
  ↓ 空一行
附件说明
  ↓ 空一行
发文机关署名
成文日期
（印章）
  ↓
附注（联系人、电话）
  ↓
版记（抄送、印发机关和印发日期）
```

**上行文**（请示、报告）：去掉发文机关标志和红色分隔线。

## 与"一般正式材料"的区别

工作总结、汇报材料、工作方案、调研报告、讲话稿、简报、专报、发言提纲、主持词、
述职报告——这些**采用机关文风，但不是法定公文**，不必机械套用上述结构。

不要看到"汇报"就写成法定"报告"；看到"方案"就要问是否有明确的**责任分工来源**，
没有就标 `[待补充]`，不要自行指定部门。

## 速查：什么必须有、什么不能有

| 要素 | 请示 | 报告 | 通知 | 函 | 批复 | 纪要 |
|---|---|---|---|---|---|---|
| 发文机关标志 | ✗ | ✗ | ✓ | ✓ | ✓ | ✓ |
| 发文字号 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 签发人 | ✗ | ✗ | 视情况 | 视情况 | 视情况 | — |
| 主送机关 | ✓ | ✓ | ✓ | ✓ | ✓ | ✗（用出席/列席） |
| 版记 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

## 写作口径（与排版分离）

以下属于**内容层**，本 skill 不管，但要知道边界：

- 不虚构文号、日期、金额、机构、人名、会议决定
- 缺失信息标 `[待补充]` / `[待核实]`
- 区分"发言意见/建议"、"形成倾向"、"待研究"、"会议决定/议定事项"
- 内部事实与公开资料隔离，不擅自联网补内部数据
- 政策引用先核验，不编造文件名、文号、原话

这些规则见 `cn-gov-soe-writing-router` 的
[事实安全规则](https://github.com/rien9036/cn-gov-soe-writing-router)——本 skill 不重复，
也不改内容。
